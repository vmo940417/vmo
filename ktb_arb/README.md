## 1. 빠른 시작 (데스크탑)

```bash
git clone https://github.com/vmo940417/vmo.git
cd vmo
git checkout claude/korean-bond-futures-arbitrage-i2ttpb
cd ktb_arb

python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

엑셀만 쓸 거면 `국채선물_차익거래_간소.xlsx`를 바로 열면 된다. 수식을 고칠 때는
**엑셀에서 직접 고치지 말고** 생성기를 수정한 뒤 재생성한다.


| `compare_simple.py` | 간소판 검증 (IMDP 셀만 숫자 치환 후 평가) |
| `기존파일_분석.md` | 사용자 기존 xlsm 분석 보고 |
| `build_ktb_arb.py` | 원본(3종목·9시트) 생성기 |
| `국채선물_차익거래.xlsx` | 생성물 (git에 커밋되어 있음) |
| `audit_wiring.py` | 참조 배선 감사 — 없는 시트/빈 셀 참조, 순환참조, 핵심 참조의 대상 행 라벨 일치 |
| `compare_sol.py` | `formulas` 라이브러리로 워크북을 실제 평가해 파이썬 독립 모델과 대조 |
| `verify.py` | Excel/LibreOffice가 캐시값을 채운 뒤 그 값을 읽어 대조하는 경로 |
| `requirements.txt` | 의존성 (Python 3.11 기준) |

### `compare_sol.py` vs `verify.py`

- `compare_sol.py` — **LibreOffice 불필요.** `formulas` 라이브러리가 수식을 직접 계산한다.
  개발 컨테이너에서 LibreOffice가 고장나 있어 이 경로를 주 검증 수단으로 썼다.
- `verify.py` — 워크북에 **캐시값이 들어 있어야** 동작한다 (`data_only=True`로 읽음).
  openpyxl이 갓 생성한 파일은 캐시값이 없어 전부 `None`이다.
  데스크탑에서 엑셀로 파일을 열고 저장하거나 LibreOffice로 recalc한 뒤 실행할 것.

## 5. 계산 모형

한국 국채선물은 **현금결제**이고, 최종결제기준가격은 바스켓 종목 수익률의 단순평균을
표준물(표면금리 5%, 6개월 이표, 잔존 n년 가상채권)의 할인율로 넣어 산출한다.

```
만기손익 = [선물 leg]  (진입가 − 표준물가격(바스켓 평균수익률)) × 1,000,000 × 계약수 × 방향
         + [현물 leg]  Σ (만기 처분단가 − 선도 목표단가) / 100 × 보유액면 × 방향
         − 거래비용

선도 목표단가 = 현물단가 + 조달이자 − 기간중 쿠폰 재투자원리금
```

- **채권 단가**: 한국 관행식 `P = [Σ CF_k /(1+y/2)^(k-1)] / (1 + y/2 × d/T)`.
  단수기간 단리, 이후 반기복리. 결과는 경과이자를 포함한 **더티(단가)** 이며
  모든 손익계산을 더티 기준으로 일관한다.
  엑셀 `PRICE()`는 단수기간도 복리 할인해서 수십 전 차이가 나므로 쓰지 않는다.
- **표준물**: 잔존 정확히 n년 → 단수기간 없음 → 폐쇄형
  `P = (5/y)(1−v^N) + 100·v^N`, `v = 1/(1+y/2)`, `N = 2n`
- **선도수익률**: 현물 더티단가를 조달금리로 캐리시킨 선도 목표단가에 대해 뉴턴법 2회로 역산.
  수렴 잔차는 `바스켓` 38행에서 확인 (~1e-9).
- **헤지액면**: `w_i × (표준물BPV / 선도BPV_i) × 거래단위`.
  종목별 수익률 1bp 변동이 선물 leg와 정확히 상쇄되도록 잡는다.
- **시나리오/만기 현물평가**: 테일러 근사가 아니라 **shift별 정밀 재할인**.
  `현금흐름` 시트에 종목당 22개(손익 1 + 시나리오 21) 재할인 열이 있다.

## 7. 알아둘 것

### 컨벡시티 잔여 리스크는 버그가 아니다 — 그리고 지금 차익보다 크다

간소판 시나리오(실제 시장 수준: 금리 4.32%, 조달 2.6%, 잔존 49일, Q=100):

```
−100bp: −27,531원/계약    0bp: +627원/계약    +100bp: −23,719원/계약
```

표준물(5% 쿠폰)이 바스켓(2.6~3.3% 저쿠폰)보다 컨벡시티가 크다.
**선물매도 + 바스켓매수는 구조적으로 컨벡시티 매도 포지션**이며 BPV 헤지로 제거되지 않는다.

현재 시장 수준에서 **락인 차익은 계약당 627원인데 ±100bp 컨벡시티 손실은 계약당
2.4~2.8만원**이다. 즉 이 거래는 지금 차익거래라기보다 **약간의 캐리를 받고 컨벡시티를
파는 포지션**에 가깝다. 진입 전 이 비대칭을 반드시 확인할 것.

### 현재 입력값의 출처

간소판의 종목코드·수익률·선물코드는 사용자의 기존 `KTB10 ... v2.xlsm` 에서 가져온
실제 값이다. 다만 결제월이 바뀌면 `[1] 결제월`과 `[3] 바스켓` 종목을 KRX 공시
기준으로 갱신해야 한다. 원본판(`국채선물_차익거래.xlsx`)의 3종목 정보는 더미다.

### 이 모형이 반영하지 않는 것

- 휴일 캘린더 (`WORKDAY()` 기반이라 공휴일 미반영. `설정`에 수동 override 셀 있음)
- 선물 일일정산(변동증거금)의 이자효과 = 테일 조정
- 최종결제기준가격(딜러 호가 집계값)과 만기일 실제 체결 수익률의 괴리 — **가장 큰 잔여 리스크**
- 레포 롤오버 리스크, 담보 haircut, 기관 유형별 이자소득 원천징수

   간소판은 종목별로 각자 IMDP 를 걸어두었으니, 25-5 를 직접 못 받으면
   `메인!B27` 을 `=B28-2.6/100` 으로 되돌릴 것
4. **레포 금리 2개** — `메인!B12`(조달, 현물매수 시 지급) / `메인!B13`(담보운용, 현물매도 시 수취).
   `B23` 이 포지션 방향에 따라 자동 선택하며 캐리와 쿠폰 재투자에 모두 쓰인다.
   **이 워크북에서 결과를 가장 크게 지배하는 입력이다** — 10bp 차이가 계약당 14,486원인데
   락인 차익은 계약당 627원 수준이다. 만기까지 확정한 term repo 금리를 넣을 것.
   기본값 2.60/2.90% 는 기존 xlsm 의 K2/K3 를 가져온 값이다.
5. **레포 term 확보** — 선물 만기까지의 조달금리. 오버나이트 롤이면 캐리 전제가 흔들린다
5. **거래비용 실측치** — 간소판 `메인!B22` 는 계약당 13,000원 가정이다.
   선물 위탁수수료 + 채권 장외 스프레드 + 최종결제 슬리피지 실측으로 교체할 것
6. **KRX 상품명세 재확인** — 거래단위, 1포인트 가치, 최종거래일 규칙

바스켓 종목 수를 바꾸려면 생성기의 `BLOCKS` / `NCOL` / `EV` 매핑과
`메인` 시트의 `"CD"` 열 루프를 함께 수정해야 한다.
